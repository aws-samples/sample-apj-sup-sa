Text-to-3D Generation with Four LLMs on Amazon Bedrock AgentCore

This architecture shows how one text prompt becomes four 3D models. Four LLMs on Amazon Bedrock each write a Blender Python script in parallel, Amazon Bedrock AgentCore Runtime runs the script in headless Blender to export a GLB, and the web page compares the four models side by side with their tokens, time taken and token cost.

1
Users open the public site. Amazon CloudFront is the only way in, with AWS WAF rate limits: 10 prompts and 2,000 requests per IP per 5 minutes.
2
CloudFront serves the React app from a private Amazon S3 bucket through Origin Access Control.
3
CloudFront forwards /api/* to Amazon API Gateway with a secret header. A regional AWS WAF blocks every request without it, so calls straight to the API fail.
4
API Gateway passes the prompt to the API AWS Lambda function.
5
The function counts today's jobs against a daily cap in Amazon DynamoDB, then saves the job with one pending result per model.
6
It invokes the worker function four times asynchronously, one per model, so all four models generate in parallel.
7
Each worker calls AgentCore Runtime with its own session, so every model runs in an isolated microVM with headless Blender.
8
The agent asks its model on Amazon Bedrock to write a Blender Python script, runs it as a sandboxed user and sends errors back for a fix (up to 3 tries).
9
The agent returns the GLB, the script and token usage. The worker saves the GLB and script to a private Amazon S3 bucket.
10
The worker records total tokens, time taken and token cost (from per-model prices) in Amazon DynamoDB.
11
The page polls the API for metrics, then loads each GLB through CloudFront's /generations/* path, which reads the bucket through Origin Access Control.
