It is not a warm standby, a backup or a multi Region setup, and it does not keep the instances in sync. For multi Region resiliency, AWS supports only Amazon Connect Customer Global Resiliency (ACGR).

📞 Step 4: Phone Number Migration (Advanced)

⚠️ Important: How a number reaches the target depends on the accounts and Regions:

  • 📍 Same account and Region: a self move with UpdatePhoneNumber. The tool does this only when the deployment opts in. The number is moved, not copied, and calls to it can fail while it moves.
  • 🛠️ Different account or different Region: AWS Support moves the numbers. One case per account, scheduled Monday to Friday, about 20 to 30 minutes per number. The number must not be the outbound caller ID on any queue at migration time.
  • 🔁 Different account and different Region: porting.
  • 📞 In every case, set the outbound caller ID on the target queues again afterwards.

The tool never moves numbers in the last two cases; the migration report lists the phone number IDs and count with the path that applies.

Moving is off in this deployment. Moving numbers is an explicit opt in (stack parameters EnablePhoneNumberMove and AllowPhoneNumberMove) and only works within one account and Region. Included numbers are listed in the migration report with the path that applies; nothing is moved.
