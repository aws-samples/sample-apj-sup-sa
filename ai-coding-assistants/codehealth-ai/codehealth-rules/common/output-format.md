# Output Format Standards

## Report Formatting Rules

All reports generated by this workflow MUST follow these formatting standards.

---

## Severity Icons (Consistent Across All Reports)

| Severity | Icon | Usage |
|----------|------|-------|
| Critical | 🔴 | Active exploits, broken deps, immediate action required |
| High | 🟠 | Known CVEs, major versions behind, deprecation |
| Medium | 🟡 | Minor versions behind, maintenance concerns |
| Low | 🔵 | Informational, opportunistic improvements |
| OK | 🟢 | Current, healthy, no action needed |

## Table Formatting Rules

1. Always use markdown tables with aligned columns
2. Include header separator row (`|---|---|`)
3. Keep cell content concise (wrap long text)
4. Use code formatting for package names and versions
5. Sort tables by severity (critical first) or alphabetically

## Code Block Rules

1. Always specify language in fenced code blocks
2. Use `bash` for shell commands
3. Use the project's primary language for code snippets
4. Include comments explaining non-obvious commands
