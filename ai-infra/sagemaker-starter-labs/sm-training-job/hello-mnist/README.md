# hello-mnist — SageMaker Training Job Example

A SageMaker Training Job example that trains an MNIST classification model in a managed PyTorch container.

The local environment is isolated and managed with **uv**, and the actual training runs on an **AWS Deep Learning Container (DLC)**.

---

## Key concept: there are two environments

This is the most important part of this example. The development environment and the training environment are completely separate.

| | ① Local PC | ② Training container (on SageMaker) |
|---|---|---|
| What it does | Submits the job with `launch.py` | Runs the actual training with `src/train.py` |
| Managed by | **uv** (`pyproject.toml`) | **AWS DLC** (torch etc. built in) |
| Required packages | `sagemaker-core`, `sagemaker-train`, `boto3` | `torch`, `torchvision` (already included in the DLC) |
| GPU/CUDA | ❌ Not needed | ✅ Included in the DLC |

> **You do not install torch locally.** The training code (`train.py`) does not run locally; it runs
> inside a container launched by AWS. That keeps the local environment light and fast.

## File structure

```
hello-mnist/
├─ pyproject.toml       # Local dependencies (sagemaker, boto3) — managed by uv
├─ .python-version      # Pins the local Python version (3.11)
├─ uv.lock              # Lock file for reproducibility (generated by uv sync)
├─ launch.py            # ① Run locally: submits the Training Job
├─ jobstatus.py         # ① Run locally: checks job status/results
└─ src/                 # ② Code uploaded to the container as a whole
   └─ train.py          #    Training script that runs inside the container
```

## Prerequisites

### 1. Tools (already installed)

- [uv](https://docs.astral.sh/uv/) — Python environment and package management
- AWS CLI v2 — for configuring credentials

### 2. AWS credentials

```bash
aws configure          # Or SSO / environment variables / EC2 instance role, etc.
aws sts get-caller-identity   # Verify credentials
```

Region selection is CONFIG `REGION`, then `AWS_REGION`, `AWS_DEFAULT_REGION`, and the default AWS configuration.

### 3. IAM execution role (SageMaker Execution Role)

The Training Job runs under a **SageMaker execution role**. Set its ARN explicitly in the
`ROLE` value in `launch.py` CONFIG. The launcher never searches account roles. If no suitable role exists, create one:

- Console: **IAM → Roles → Create role → Use case: SageMaker** →
  attach the `AmazonSageMakerFullAccess` policy (sufficient for training)
- Choose the role intended for this lab and copy its ARN into `ROLE` before submitting a job.

Minimum permissions the role needs: SageMaker training, read/write on the artifact S3 bucket, ECR pull (DLC), and CloudWatch Logs.
`AmazonSageMakerFullAccess` covers all of these.

---

MNIST is downloaded inside the training container, which needs internet access. Network isolation or a VPC
without an internet route (such as NAT) prevents this download. For S3 input prepared locally, see
[byoc-mnist](../byoc-mnist/README.md).

## How to run

Run all commands from this folder (`hello-mnist/`). `uv run` automatically creates a project-specific
virtual environment (`.venv`) and runs inside it, so you do not need to `activate` anything.

### Step 0. Set up the environment (first time only)

```bash
uv sync
```

Reads `pyproject.toml`, creates `.venv`, and installs `sagemaker-core`, `sagemaker-train`, and `boto3`.

### Step 1. Validate the configuration (recommended, no AWS charges)

```bash
uv run launch.py --dry-run
```

Prints only the region, DLC image URI, and instance settings **without submitting** a Training Job.
Example output:

```
region   : ap-northeast-2
image    : 763104351884.dkr.ecr.ap-northeast-2.amazonaws.com/pytorch-training:2.7.1-cpu-py312
instance : ml.c6i.2xlarge
epochs   : 3
[dry-run] Not submitted. Configuration check complete.
```

### Step 2. Submit the job

```bash
uv run launch.py
```

- The default is a **CPU instance (`ml.c6i.2xlarge`, 8 vCPUs)**.
  New accounts often have a GPU quota of 0, so CPU is the safest choice for "it just works."
- By default it **waits until completion** and streams the logs in real time (it finishes in a few minutes).
- The submitted job name is recorded in `.last_job.json`.

### Step 3. Check status / results

```bash
uv run jobstatus.py                         # Check the last job in .last_job.json
uv run jobstatus.py hello-mnist-2026-...    # Check a specific job by name
```

Once the job is `Completed`, it prints the S3 path of the model artifact (`.../output/model.tar.gz`).

## Changing settings

All settings are in one place: the **CONFIG block** at the top of `launch.py`. Just edit the values and run it again.

```python
EPOCHS = 3
INSTANCE_TYPE = "ml.c6i.2xlarge"   # To train on GPU, e.g. "ml.g4dn.xlarge" (requires account quota)
FRAMEWORK_VERSION = "2.7.1"        # PyTorch DLC version (e.g. "2.7.1", "2.8.0")
MAX_RUN_SECONDS = 3600             # Maximum run time (safeguard). e.g. 86400 (24h)
WAIT = True                        # If False, returns immediately after submission (asynchronous)
ROLE = "arn:aws:iam::<account-id>:role/<role-name>"  # Required execution role
REGION = None                      # AWS region. If None, uses the default session region
```

For example, to train for 10 epochs on GPU, change to `INSTANCE_TYPE = "ml.g4dn.xlarge"` and `EPOCHS = 10`,
then run `uv run launch.py`. We recommend checking with `--dry-run` first.

## Monitoring in the console

Once the job is submitted, in the [SageMaker console](https://console.aws.amazon.com/sagemaker/):

1. Check the status in the **Training → Training jobs** list (`InProgress → Completed`)
2. Click the job → **View logs** (CloudWatch) for real-time logs
3. The `test:accuracy` graph under **View algorithm metrics**
   (this metric is produced by the regex in `launch.py` parsing the `test_accuracy=...`
   output of `train.py`)

## How it works (summary)

1. `launch.py` uploads the entire `src/` directory to S3, specifies the managed PyTorch DLC as the training image,
   and submits the Training Job with `ModelTrainer.train()` (by default it waits until completion).
2. SageMaker launches an instance and runs `train.py` inside the DLC container in the form
   `python train.py --epochs 3` (hyperparameters are passed as CLI arguments).
3. `train.py` downloads MNIST, trains a CNN, and saves the model to `SM_MODEL_DIR` (`/opt/ml/model`).
4. When the job ends, SageMaker packages that folder as `model.tar.gz` and uploads it to the S3 output path.
5. The instance is shut down automatically (you are charged only for the training time).

## Common issues

| Symptom | Cause / Fix |
|---|---|
| `Set ROLE in launch.py CONFIG` | No execution role exists. See the **IAM execution role** section above, then set the ARN in `ROLE` in CONFIG |
| `Could not find a region` | Set a default region with `aws configure`, or set `REGION` in CONFIG |
| `ResourceLimitExceeded` (GPU) | The quota for that instance type is 0. Run on CPU or request an increase in Service Quotas |
| Job is `Failed` | Check `FailureReason` with `uv run jobstatus.py` → see the detailed stack trace in CloudWatch Logs |
| Data download fails | Happens when the training instance is configured as VPC-only (no internet access). In that case, upload MNIST to S3 and inject it as an input channel |
